# Scope modes

Ported from gstack plan-ceo-review / graphstack strategist. Pick one and commit. Do not silently drift.

- **Expansion** — The opening is too small for the opportunity. Push scope up only when a materially better product is still shippable. Every expansion is an explicit user opt-in.
- **Selective Expansion** (default) — Core wedge is right. Surface adjacent opportunities as named cherry-picks; do not fold them in silently.
- **Hold Scope** — The wedge is already correct. Maximum rigor on what's there. No quiet adds or cuts.
- **Reduction** — Overloaded. Strip to what proves the core hypothesis. Name each cut.

**Defaults:** bug/hotfix/refactor → Hold Scope. Open-ended "think bigger" → Expansion. Most feature work → Selective Expansion.

## Premises

Name assumptions that have not been established. Shaky premises are Lookout bait.

## Six-month check

One sentence: if this ships as scoped, is the regret "too little to matter" or "more than we needed to learn"?
